# The small apps: myVST (`vikings.html`), myBangers (`bangers.html`), myFAM (`index.html`)

- **`vikings.html` (melbostads.com/vikings, myVST) is a second, tiny app** over `api/vikings.js` (`test-vikings.mjs`). **Its GET is public and its POST login-gated — the opposite of `plans.js`** — because logged-out visitors see the names as text. Schedule and History are read-only for everyone; editing lives only in the login-only Admin tab.
- **The myVST schedule is home games only**: `nflSchedules.teams.MIN` plus the Vikings-only `nflPreseason` (`fetchNflPreseason`), kept out of `nflSchedules` so myFFL's bye logic never sees it, and dropped when its season isn't the schedule's. Names and face values are per-game patches keyed `${season}-${week}` (preseason `-p${week}`, playoffs `-po1..3`). Playoff rows are hand-typed and hidden from logged-out viewers until filled.
- **Earlier myVST seasons come from `data/vikings-history.json`** (`backfill-vikings-history.yml`, manual, re-run yearly; `test-vikings-history.mjs`), since the snapshot carries only the current one. A season with a `postseason` list takes its playoff rows from it; otherwise they're typed by hand.
- **Seat ids and owners live in `vikings.html`'s `SEAT_GROUPS`**, per season via `since`/`seasons`. Don't renumber a seat once names are saved.
- **myVST's Quick Links and Tasks are their own Upstash keys, never the plans document**: `vikings:quicklinks` (`?resource=quicklinks`, public GET, login-gated POST; it is also the header toolbar) and `vikings:tasks` (`?resource=tasks`, login-gated on GET too).
- **`bangers.html` (melbostads.com/bangers, "myBangers") is a third small app** over `data/bangers.json`: Winners and Nominees tabs for everyone, a login-only Admin tab. Admin's Save POSTs to `api/bangers.js`, which **commits the file straight to `main`** (like `save-leagues.js`, same `GITHUB_CONTENTS_TOKEN`), so its validation is the only guardrail; `test-bangers.mjs` also validates the committed file. A stale save is refused by blob sha (`baseSha`). Ids must be letters and digits. Pages republishes a minute or two after a save.
- **myBangers voting lives in Upstash, never the repo**: one hash `bangers:votes:<yearId>` per year, field = lowercased, whitespace-collapsed name. **A vote is `HSETNX`, so one name casts one vote per year even under a race — don't turn it into read-modify-write of a document.** `POST resource=vote` is public but needs Vercel's `BANGERS_VOTE_PASSWORD` (500 when unset, never open; wrong guesses rate-limited per IP, failing open, shared with nominating via `passwordGate`); it checks the year's phase and the nominee against `main`'s `data/bangers.json`, not the caller. **Nobody may vote for their own nomination** (`isOwnNomination`: voter name vs the nominee's `by`, case/punctuation-insensitive, first-word match; best effort). The Nominees tab's public "X Votes" plaque line (not Winners) reads `?resource=tally` (counts per nominee, never names). `resource=votes` (ballots) and `resource=ballot` (Admin change/add/delete of a ballot, which skips the self-vote and phase checks) are login-gated. `test-bangers.mjs` covers the flow.
- **Each myBangers year has one phase, `bangers:year-states`** (`{ phases: { yearId: 'nominating' | 'voting' } }`; no entry = Complete, so history needs no data). `GET ?resource=state` is public, `POST` login-gated; the Years card's Status dropdown saves at once, and is disabled for a year not yet saved to the file (the server can only open a year it finds there). **The server enforces the phase on every vote (`voting`) and nomination (`nominating`); the page only hides.** The two old lists (`bangers:voting`, `bangers:nominating`) are read as a fallback until the first save (`readPhases`). **Hiding a Nominations Open year from Winners, Nominees, Stats and the header count (`shownYears`) is cosmetic — nominations are committed to the public `data/bangers.json`** — so don't treat it as secrecy. `POST resource=nominate` adds a nominee to that file (same password gate): the commit is a read-modify-write on the file's sha, **retried and re-checked on a lost race** so an Admin save or another nomination is never overwritten; keep the duplicate, one-per-person (`isOwnNomination` vs each `by`) and `MAX_NOMINEES` checks inside that loop. The page deliberately doesn't add the nominee to its own list, or Admin's `baseSha` stale check would misfire; a nomination landing while Admin edits makes the next Save a 409.
- **myBangers and myFAM carry the same Tasks and Quick Links cards as `vikings.html` — keep the three in step.** Each has its own Upstash keys (`bangers:*` via `api/bangers.js`, `fam:*` via `api/fam.js`, `?resource=tasks|quicklinks`, reusing vikings.js's validators; **never share keys**) and the same gating: quick-links GET public, tasks GET and every POST login-gated. `BANGERS_TASKS=1` / `FAM_TASKS=1` point `fetch-tasks`, `mark-tasks-done` and `rename-task-category` at them (`test-fam.mjs`).
- **`index.html` is myFAM, the home page.** Its Family tab's Photos and Calendar read public iCloud feeds via `api/fam.js` `?resource=photos|calendar` (`api/_lib/sharedalbum.mjs`, `calendarfeed.mjs`; `test-shared-album.mjs`, `test-calendar-feed.mjs`). The feed links live in Vercel's `FAM_PHOTOS_ALBUM`/`FAM_CALENDAR_ICS`, never committed. **Photos' cache is tied to Apple's signed image links** (`photoCacheMs`: until 10 minutes before the earliest `url_expiry`, floor 1 minute, ceiling 12 hours, 5 minutes if Apple sends none), never a fixed multi-hour timer, or the links are dead when served. `&refresh=1` skips the cache and needs the Bearer token; the card's Refresh button shows only when logged in. **The Photos grid pages at 3 rows**, so the page size is columns × 3, read back from the grid (`photoColumns`; a collapsed card can't be measured, so a `ResizeObserver` redoes it on expand). A page's thumbnails load only when it is shown, so paging and opening a photo re-read the album first when the links are within a minute of expiry (`currentPhotos`). **Sort and filters (`famPhotosView` in localStorage) run in the browser over the fetched album** (`added` comes from the server for the Recently added sort); a saved choice the album no longer offers is ignored, and a filter that could change nothing is hidden. The viewer steps through the current list by id.
